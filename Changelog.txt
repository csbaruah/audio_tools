DICE-SKIT CHANGELOG
===================

Newest first. Dates are when each change was made (local time; times in the
Sep 11 entries are UTC). Section numbers (sec.) refer to
docs\audio-concat-study.md.


2026-10-17  GitHub Actions runs the Make test target
    Pull requests to main and pushes to main now install GNU Make and run
    "make test", keeping automated checks consistent with local development.

2026-10-17  Named test results and saved test logs
    "make test" now shows each pytest name and pass/skip/fail result, then
    checks formatting. Both command outputs are streamed to the terminal and
    saved in a timestamped output\log\tests-*.log file.

2026-10-17  Make targets for test, Windows release and cleanup
    Added make test; make release-windows runs tests before packaging (make
    release is an alias); make clean removes only output\release\. make android
    clearly reports that a framework must be selected before APK builds.

2026-10-17  Windows console release prototype (sec. 16)
    Added a Makefile-driven builder for output\release\modaud.exe. It accepts a
    project folder and existing stitch options, bundles FFmpeg/FFprobe, and
    includes a three-line sample. The packaged sample built a 190.2-second
    master successfully.

2026-10-12  Automated tests and pull-request checks
    Added fixture-based tests for folder migration, settings and CSV pre-flight
    validation. GitHub Actions runs the suite and checks test formatting for
    pull requests targeting main.

2026-10-08  Input / in-out / output folders and "clean" (sec. 14)
    Folders now sit under input\ (script, recordings), in-out\ (TTS) and
    output\ (master, work, log), each relocatable in dice-skit.json. Old
    projects move automatically on first run, safely. "stitch_mp3.py clean"
    empties master and work after confirmation, keeping logs.

2026-10-07  t-m-loop cuts a longer background (sec. 10.4)
    With exactly t-m-loop, the mix now always lasts as long as the line: a
    longer background fades out and is cut where the line ends, instead of
    playing on. Other -loop cues still let a longer background play on.
    Existing masters unchanged.

2026-10-07  Looping background and open-ended cues (sec. 10.4)
    New cue t-m-loop: both tracks start together; a background shorter than
    the line repeats until the line ends, with a short fade at each seam.
    The last cue segment no longer needs a duration (t-m). Existing cue
    strings produce identical masters.

2026-10-07  Character mismatch allowed when strict=0 (sec. 9.6)
    A file whose character name differs from its CSV row, e.g.
    23_24_Shakuni.m4a or a Dhritrashtra spelling, no longer stops a strict=0
    build: it is listed, counted as a problem, and used. A strict build still
    stops. The other three mandatory checks are unchanged.

2026-10-05  README.txt and Changelog.txt
    Added a user guide covering the tool's features, installation, use without
    configuration, command-line and dice-skit.json options, the Sarvam key
    setup and each file's role. Added this changelog.

2026-10-05  Original script deleted
    Removed stitch_aud.py, the unused pre-split script. It no longer compiled
    and held stale settings copies; everything it did now lives in the current
    modules. Copies remain in backup\v2 to v9. Recorded in sec. 5.1.

2026-10-05  Settings file: dice-skit.json (sec. 12)
    All 33 settings moved from Python constants to a commented JSON file,
    checked on load: typos, wrong types and out-of-range values stop the run.
    The command line still overrides it. The run log records each value's
    source. The API key is never stored there.

2026-10-05  Uniform dialogue loudness (sec. 11)
    Every line is measured and given one fixed gain to -19 LUFS, with a -1 dBFS
    peak limit, before mixing and joining. Measured spread fell from 10.0 dB to
    0.1 dB. Corrects the encoder's 0.4 dB loss. loudness=0 turns it off for one
    run.

2026-10-05  Settings and API-key design (sec. 12)
    Specified the JSON settings file: "_" keys as comments, GUI-safe saving,
    and what stays out. Tested Windows DPAPI encryption. Decided the Sarvam key
    never goes in the file; tts.api_key_source points to .env or Windows
    Credential Manager.

2026-10-05  Loudness problem found (sec. 11)
    Measured all 15 lines: a 10 dB spread between the loudest and quietest,
    varying by recording rather than by character. Found 0-SAMAY.mp3 already
    clipped. Proposed per-line leveling to a common target.

2026-10-05  Background score under a line (sec. 10)
    New background_score and score_cues CSV columns mix music under a line. Cue
    strings like b-2s-m-10s-b-5s set which track is loud when; t- starts both
    together. Faded track -14 dB, never silent. Mixes cached. Faults follow the
    strict rules.

2026-10-05  Background score designed and prototyped
    Proved overlay mixing feasible with FFmpeg and agreed the cue-string rules:
    first track solo, quiet track faint but audible, nothing trimmed, music back
    to full volume when the line ends. Trial mixes generated in human_gen\.

2026-10-05  Filler columns kept
    Reviewed moving sound effects into rows of their own and rejected it: it
    would change the loader, file matching, gap rules and TTS just to express
    four cues. The filler_before and filler_after columns stay.

2026-10-04  Automatic versioned backups
    A Claude Code hook copies every source file into backup\vN before the first
    edit of each request, skipping unchanged snapshots. backup\v1 holds the
    files from before the mandatory checks.

2026-10-04  Mandatory checks and dry run (sec. 9)
    Four checks now always abort, whatever strict says: CSV missing, character
    name mismatch, no character name, two files for one take. Added dry_run=1
    to run every check without building. Every fault is reported in one pass.

2026-09-14  Script-revision rules specified (sec. 9)
    Treat each take number as a permanent ID: never renumber; reorder by moving
    rows; new lines get the next free number. Specified the four mandatory
    checks and the dry-run behaviour, then not yet built.

2026-09-11  Trailing fillers and "no gap"
    Added the filler_after column, empty meaning nothing appended, and a
    generated 10-second long_filler.mp3. "N" in filler_before removes the gap
    before a line.

2026-09-11  Two source folders and run logs
    Audio is now read from human_gen\ (recordings, preferred) and machine_gen\
    (TTS); dialogues-mp3\ holds only the master. Each run writes a log with
    every warning and a per-line source table.

2026-09-11  Google Drive download and setup guide
    Added fetch_drive.py to download recordings from a shared Drive folder,
    with truststore for corporate HTTPS inspection. Added the new-PC setup
    guide (sec. 0).

2026-09-11  Per-row leading fillers (sec. 8)
    Added the filler_before column: empty gives a 2-second pause, a filename
    plays that audio before the line. The separate intro setting was removed;
    the opening music is now row 0's filler.

2026-09-11  .m4a/.aac/.mp4 support and flexible names (sec. 7)
    Non-MP3 inputs are converted to 24 kHz mono 128 kbps MP3 and cached. Files
    match their row by leading take number alone, so names like
    129_Krishna.m4a work.

2026-09-11  strict mode
    Added strict=0 to build from whatever audio exists and report the rest;
    strict=1, the default, aborts without touching the master. The existing
    row limit (e.g. python stitch_mp3.py 20) was kept.

2026-09-11  Pipeline split and FFmpeg-free joining (sec. 1-6)
    Split stitch_aud.py into generate_mp3.py (TTS, disabled), stitch_mp3.py and
    shared modules. Added a built-in MP3 joiner needing no FFmpeg. Found the
    intro's 22,050 Hz rate clashing with 24,000 Hz dialogue and added a
    pre-flight format check.
